# Doc closure & code-liveness audit — 2026-08-28

Triggered by a gap found by hand in [quote.md](quote.md): the doc covered
`denowatts-backend/src/quote/` thoroughly (921 lines, 60+ citations) while the feature
actually spans three backend modules. The question this audit answers is whether that
was a one-off or a pattern, and where else it bites.

**It is a pattern.** The cause is structural, not careless: the procedure in `CLAUDE.md`
traces a feature *forward and inward* (UI → route → controller → service → db) and stops
at the service boundary. It never follows a service's **outbound** dependencies, and it
cannot see **inbound** writers (webhooks, callbacks, jobs) that mutate the same data from
outside the module folder.

---

## Method

Two independent signals were computed per source file, then crossed.

- **LIVE** — reachable in the import graph from a real runtime entry point
  (`denowatts-backend/src/main.ts`; `denowatts-portal/src/main.tsx` + the generated route tree).
  Import specifiers resolved including portal path aliases (`@features`, `@common`, …) and
  barrel `index.ts` files.
- **CITED** — the file path appears in at least one `flows/*.md` doc.

Specs, `.d.ts`, and generated files are excluded throughout.

### Known limitations

- **Dynamically loaded assets read as dead.** Handlebars templates (`*.hbs`), and anything
  resolved by runtime string rather than `import`, are invisible to the graph. Non-TS files
  were excluded from the liveness verdict for this reason.
- **CLI-invoked scripts read as dead.** Migrations under `*/migrations/` are not imported
  from `main.ts` and are correctly unreachable — they are a false-positive class, not dead code.
- Liveness means *reachable*, not *executed*. A file behind a disabled feature flag or an
  unused GraphQL operation still counts as LIVE.

### B. Why one gap contaminates many docs

`shared/*` is imported by feature modules, so an undocumented integration silently
weakens every doc downstream of it:

| Integration | LOC | Imported by | Docs that depend on it |
|---|---:|---|---:|
| `shared/email` | 496 | auth, events, quote, report, storage, webhooks | **15** |
| `shared/google` | 112 | sites, webhooks | **9** |
| `shared/docuseal` | 1,073 | quote | 1 |
| `shared/hubspot` | 1,612 | quote | 1 |

`shared/email` is the widest: **15 docs** say some version of *"emails the owner"* and not
one cites the 328-line service that decides recipients, templates, and failure handling.

### C. Orphaned code — excluded, not investigated

28 portal files (3,336 LOC) are unreachable from any entry point, plus 2 backend migration
scripts that are unreachable by design (CLI-invoked, a false-positive class).

**These are out of scope.** Liveness exists here only as a *filter* — it tells us which code is
connected so the docs describe the real business and nothing else. Orphaned code is not a
documentation subject, is not ranked, and is not worth anyone's reading time. The full list is
reproducible from `scripts/closure-audit.py` if it is ever needed for a cleanup task, which is
an engineering concern rather than a docs one.

The one thing worth carrying forward: an orphan can *look* like a business rule. A
"Rejection Note" modal exists under quote-management with no importer, no backend field, and no
`REJECTED` status. Filtering by liveness is what keeps such things out of the docs.

### E. Unresolved uncertainty markers

**26 markers across 17 docs** (`UNCLEAR`, `presumably`, "flag for human review",
"not visible in this"). These split in two:

- **Legitimately external** — genuinely outside this repo, correctly scoped and should be
  kept: `status-logs:255` (no producers in this codebase), `tests:174` (external Python
  service), `status:134`/`status:195` (rollup rules not in this repo).
- **Resolvable but never revisited** — the failure mode. `quote:518` and `quote:892` both
  guessed at a DocuSeal webhook that a single grep locates in
  `denowatts-backend/src/shared/docuseal/docuseal.controller.ts:20`. Also worth a second
  pass: `authentication:330`, `field-setup:109`, `companies:295`, `analytics:205`.

The defect is not that hedges were written — it is that nothing ever consumed them.
They were write-only.

## Process changes

1. **Follow the edges outward.** After tracing a feature, read `<feature>.module.ts`
   imports and the service constructor's injected dependencies. Each is either documented
   or listed in an explicit **Out of scope** block with a reason. No silent omissions.
   *(Catches `shared/*` — 60% of the gap.)*
2. **Find the other writers.** Grep the whole backend for writes to the feature's schema
   fields and status enum. Any controller, webhook, callback, or job that mutates them is
   part of the flow. *(Catches the DocuSeal callback.)*
3. **"Done" is a coverage number, not a judgment.** Every business-logic file in a
   feature's dependency closure is cited or explicitly excluded. This script computes it;
   fold it into the drift/brain tooling so closure regressions surface automatically.
4. **Hedges are a work queue.** Generate `OPEN-QUESTIONS.md` from the markers and resolve
   them as tasks. A hedge is permitted only after a real attempt to resolve it.
5. **State machines are read from the guard, not the intent.** For any status enum,
   document the actual comparison function and enumerate reachable transitions.
   *(quote.md said "moves forward only"; the rank check at `quote.service.ts:329-334` is
   non-decreasing, which permits PENDING → SHIPPED skipping SIGNED.)*
6. **Use liveness as a scoping filter.** Confirm a file is reachable before documenting it, so
   docs describe connected behaviour only. Orphans are simply excluded — not catalogued, not
   annotated, not written about.

## Suggested burn-down order

1. **`shared/email`** — 1 doc, unblocks accuracy in 15.
2. **`shared/docuseal`** — the signing callback is where a prospect becomes a customer
   (auto-creates Company and Site). Highest business value per line.
3. **`shared/hubspot`** — 1,612 LOC; first question to settle is live vs. legacy, since
   `CREATE_ORDER` is defined in the portal but imported nowhere.
4. **`sites` inverters/modules** (628) and **`status-logs`** (369).
5. The 5 missing catalog pages, then the resolvable hedges.
